## 2026-08-12 - Preventing Buffer Allocation Overhead in WebGL Render Loops
**Learning:** In WebGL-based visualization or simulation applications, recreating and re-uploading buffer data using `gl.createBuffer()` and `gl.bufferData()` within the rendering loop (specifically inside utility helpers like `blit()`) introduces massive CPU/GPU synchronization and allocation overhead. In this codebase, each frame invoked `blit()` up to 17 times, leading to 34 brand new GPU buffers allocated and discarded every single frame. This triggers significant garbage collection pauses and limits frame rate stability. Creating the static geometry (full-screen quad) vertex and index buffers once during initialization and binding/reusing them per-frame completely eliminates runtime GC overhead and GPU data transfer bottlenecks, maintaining fluid animation smoothness at a stable 60 FPS.
**Action:** Always verify if helper functions inside WebGL/Canvas rendering loops are allocating memory or WebGL resources dynamically. Ensure all static buffers, textures, and attributes are instantiated once during start-up, and only bind/use them in the frame loop.
